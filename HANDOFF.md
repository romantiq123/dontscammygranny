## TL;DR

Офлайн Android-детект мошенничества для пожилых (RU/KZ), под грант Sentient.
Архитектура ROMA (Atomizer→Planner→Executor→Aggregator) реализована нативно на Kotlin.
Рабочий прототип: собирается, ставится на устройства, **on-device LLM подтверждён в бою**.

Главный открытый блокер прежний — **бенч моделей на референс-устройстве** (ADR-002/003).

## Как собрать и прогнать тесты

Нужен **JDK 17–21** (Gradle 8.9 не идёт на JDK 24), Android SDK, NDK `26.1.10909125`,
CMake `3.22.1`. Путь к SDK — в `local.properties` (в `.gitignore`).

```bash
./gradlew :core:test           # чистый JVM, 62 теста, без Android SDK
./gradlew :app:assembleDebug   # → app/build/outputs/apk/debug/app-debug.apk
```

Отчёт тестов: `core/build/reports/tests/test/index.html`.
Установка: `adb install -r app/build/outputs/apk/debug/app-debug.apk`.

Python-прототипы (эталон поведения — если правишь regex/агрегатор, сверься):

```bash
python -X utf8 regex_layer.py && python -X utf8 call_detect.py
python -X utf8 aggregator.py  && python -X utf8 validate_gbnf.py
```

> ⚠️ **После правок нативной части нужен ЧИСТЫЙ пересбор** (иначе ninja переиспользует
> старые объектники и «ничего не меняется») —
> [ENGINEERING_NOTES §5.1](ENGINEERING_NOTES.md#51-a-clean-native-rebuild-is-mandatory).
>
> ⚠️ Если `./gradlew` падает с `Unable to establish loopback connection` — это ограничение
> терминала, а не проект; есть рабочий обход для `:core` —
> [ENGINEERING_NOTES §5.2](ENGINEERING_NOTES.md#52-gradle-fails-to-start-in-an-ai-agents-terminal-loopback--with-a-working-workaround).

## Открытые технические долги

Отсортировано по важности. Разбор причин, где он есть, — в ENGINEERING_NOTES.

1. **Гейт эскалации к LLM слишком узкий.** LLM вызывается только при
   `atom.category != "none"` — то есть он может лишь **подтвердить** находку регекса, но
   **не поймать то, что регекс пропустил** (а по ADR-007 он нужен именно для этого).
   Любой новый скам-фразинг мимо регекса = мимо LLM. Кандидат: эскалировать и на «слабый
   сигнал» (есть URL / упомянут банк / есть слово «код») без полной категории. Меняет
   частоту вызовов LLM → решать с учётом бенча и hit-rate кэша.
2. **Бенч моделей (ADR-002/003) не проведён** — блокер финального выбора модели.
   Код даёт, на чём мерить (latency/RAM), но не заменяет замер.
3. **Всё, что сделано 2026-07-27, не проверено на устройстве** — кэш вердиктов, контакты,
   `CallStateWatcher`, `BankAppMonitor`, UX скачивания. Компилируется, `:core:test` зелёный.
4. **`AlertPresenter` неполон (ADR-013).** Есть heads-up + вибро; нет `TextToSpeech` и
   полноэкранного `USE_FULL_SCREEN_INTENT` — последнее упирается в непроверенный вопрос,
   распространяется ли льгота FSI на роль `ROLE_CALL_SCREENING`.
5. **Дублирование путей по SMS.** `RegexAtomizer` (текстовые категории) и
   `ShieldEngine.onSms()` (OTP/импперсонация в контексте звонка) перекрываются: оба
   вызываются, берётся более severe результат. Работает, но формально не решено —
   кандидат в мини-ADR.
6. **Не оформлены ADR** для трёх реализованных расширений: мессенджер-звонки (расширение
   ADR-011), наблюдаемые приложения, кэш вердиктов.
7. **Семантический кэш (путь B)** — матч перефраза через эмбеддинги. Не сделан; решать по
   hit-rate лексического пути A на реальных цифрах.
8. **Дефолтные списки не выверены на устройстве:** пакеты банков в `WatchedApps`,
   пакеты мессенджеров в `VOIP_CALL_PACKAGES`, allowlist официальных номеров банков.
